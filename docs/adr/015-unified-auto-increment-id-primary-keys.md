# ADR-015：所有数据表统一使用 id 自增物理主键

- 状态：已接受，真实 GoldenDB 待验证
- 日期：2026-09-10
- 负责人：服务团队
- 决策人：用户指定
- 关联需求：所有数据表主键字段必须为 `id BIGINT AUTO_INCREMENT`
- 取代范围：ADR-005 的 `IdType.INPUT` 物理主键决策、ADR-013 的产品复合物理主键决策，以及 `ARCHITECTURE.md` 中“不依赖数据库自增”的约束

## 背景

现有十张 Flyway 受管表混用 UUID、业务单列、复合键和 `event_id` 作为主键。用户明确要求直接把最终物理主键统一为字段名 `id`、类型 `BIGINT`、数据库自增，禁止保留原主键后另加 `pk_id`。

会话、消息、回答和文件的原 UUID 已进入 REST、SSE、幂等、上下文和 OBS 对象键。直接删除这些值会造成无授权的数据丢失并破坏现有接口，因此本决策只删除其主键身份：原值改名为 `public_id`，作为普通唯一业务字段继续服务公开契约。

## 决策

1. 所有现有和未来数据表只能有一个物理主键：`id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY`。
2. 禁止使用 `pk_id`、UUID、外部编码或复合业务键作为物理主键；`qa_answer_event.event_id` 原值无损改名为 `id`，继续作为 SSE 事件序号。
3. `qa_conversation`、`qa_message`、`qa_answer` 和 `qa_file` 的原 UUID `id` 改名为 `public_id` 并增加唯一约束，不再是主键。领域和 API 中的 UUID `id` 明确映射到该公开字段。
4. 原复合或单列业务主键改为唯一键，继续保证反馈、停止任务、会话上下文、附件关系和产品快照的业务不变量。
5. 本次不把全部逻辑引用改成数值外键。`conversation_id`、`answer_id`、`question_id` 和 `file_id` 仍保存公开 UUID，并关联父表 `public_id`；在 GoldenDB 分片、同置和外键策略确认前不得虚构数值外键方案。
6. 数值主键只存在于持久化适配器，不进入领域对象、REST/SSE 资源 ID、OBS 对象键、鉴权判断、幂等指纹或日志关联。持久化 Record 严格按数据库字段转换为 Java 小驼峰命名，因此物理主键列 `id` 对应字段 `id`，公开标识列 `public_id` 对应字段 `publicId`。
7. 历史迁移 `V1`～`V7` 不修改；`V8`～`V17` 每个版本只切换一张表，降低非事务 DDL 中途失败的影响范围。
8. 由于旧、新结构中 `id` 含义不同，本次是需要停写和协调部署的 Schema 合同切换，不支持旧、新应用普通滚动混跑。生产配置必须显式提供 `PROD_FLYWAY_TARGET=17`，缺失时失败关闭。

## 后果

- 所有表的物理主键名称、类型和生成方式一致，且不存在 `pk_id`。
- 公开 UUID、稳定分页、幂等、上下文来源 ID、附件引用和 OBS 对象键保持兼容。
- 旧应用仍查询 UUID `id`，不能直接运行在新结构上；回滚必须使用预制兼容版本或恢复一致性备份，不能只回滚旧二进制。
- 主键交换可能重建表及二级索引；分布式自增可能造成热点，必须由真实 GoldenDB 验证。

## 迁移与失败语义

1. 生产执行前冻结写流量、排空活动任务、取得一致性备份并完成重复键和孤儿引用检查。
2. 按 `V8`～`V17` 逐表执行，每个版本后核对行数、公开 ID、业务唯一键和关键索引；任一步失败立即停止后续版本。
3. `qa_answer_event` 只改列名，不重排或重新生成历史值，确保既有 `Last-Event-ID` 数值不变。
4. DDL 不做逆向回滚。失败后优先通过新的前向迁移修复；需要退库时只能恢复已验证的一致性备份，并按批准的 RPO 处理切换后写入。
5. 若目标 GoldenDB 不支持该原地合同切换，必须用新 ADR 改为影子表、数据回填和受控切换，不得猜测兼容性。

## 验证

- H2 最终结构测试检查全部十张生产表的唯一主键均为 `id BIGINT AUTO_INCREMENT`，并检查原业务唯一键。
- 原生 MyBatis 集成测试证明数据库自动生成内部 `id`，领域与 API 仍返回原 UUID `public_id`；生成键与命名契约测试验证显式插入、ResultMap 和持久化 Record 均遵循数据库字段转小驼峰规则。
- 迁移契约测试检查 `V8`～`V17` 逐表覆盖、无 `pk_id`，以及事件序号原值改名路径。
- 完整门禁为 `mvn -B -ntp clean verify`。
- H2 和迁移文本检查不能证明 GoldenDB 方言、锁时间、分片自增、故障切换或存量迁移，以上均为生产发布阻塞项。
