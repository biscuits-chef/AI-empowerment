# ADR-011：前端维护 Agent 目录并由后端按类型路由

## 状态

已接受，2026-09-03。

## 背景

统一工作台的 Agent 名称、图标、排序和未开放提示属于前端导航配置，不需要通过后端目录接口动态获取。旧设计要求页面初始化调用 `GET /api/v1/agents`，既增加了首屏依赖，也可能因前后端版本不一致导致整个工作台加载失败。

前端配置不能成为服务端安全依据。用户可绕过页面直接构造请求，因此后端仍须识别 Agent 类型、校验开放状态与权限，并只路由到明确存在的处理链路。

## 决策

1. 删除 `GET /api/v1/agents`，后端不再维护供页面展示的 Agent 名称、图标、顺序和说明。
2. 前端在本地配置 Agent 目录，第一阶段输入区默认且仅开放“智能问数”，稳定类型为 `SMART_DATA`。
3. `POST /api/v1/chats/{chatId}/questions` 请求体必须携带 `agentType`。
4. 后端使用独立枚举白名单解析 `agentType`，并在应用层路由。第一阶段只将 `SMART_DATA` 路由到现有智能问数链路。
5. 缺失、未知或尚未开放的类型返回 `400`，不得创建回答或调用任何下游依赖。
6. 后续增加 Agent 时，前端展示配置和后端执行能力分别发布；只有两端均就绪且后端权限校验完成后，前端才能把该类型标记为可用。

## 影响

- 页面初始化只需加载会话数据，不会因 Agent 目录接口失败而显示全局“请求未完成”。
- Agent 展示调整无需修改后端，但新增可执行 Agent 仍必须实现后端路由、权限、测试和审计。
- 前后端以稳定的 `agentType` 字符串作为契约，不以中文名称作为接口参数。
