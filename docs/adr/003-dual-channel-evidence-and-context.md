# ADR-003：采用双通道证据对账与受控上下文

## 状态

已接受，生产字段规则待确认。

## 背景

第一阶段需要回答产品/交易基础信息和产品最新信息。知识库文档与业务数据库可能存在版本延迟、字段口径差异或真实冲突；只把两段文本交给大模型会产生静默选边、无依据补全和遗漏风险。多轮问题还可能使用“这个产品”“上一笔交易”等指代，不能只处理当前问题。

## 决策

1. 在检索前识别受支持意图并提取产品、交易、文档类型和时间等实体。
2. 知识库与业务数据库作为两个独立证据通道，不把任一通道的自然语言结果直接视为最终答案。
3. 使用业务字段字典执行标准化、版本判断和确定性对账，结果为一致、冲突或证据不足。
4. 冲突时由应用层强制展示两边数据、来源、冲突字段和人工复核提示；大模型只能整理语言。
5. 证据不足或意图低置信度时拒绝生成事实性答案，并要求补充标识或澄清。
6. 模型请求包含结构化意图、最近有效历史和证据状态。结构化实体与待追问状态按 ADR-007 持久化；生产环境还需实现 Token 自适应会话摘要。

## 后果

- 回答链路增加意图识别与证据对账端口，外部平台可以替换且便于契约测试。
- 产品字段字典、权威来源、版本规则和冲突容忍度成为业务必须维护的配置资产。
- 不能对任意未知输入承诺数学意义上的零幻觉，但可以将“无证据事实断言为零”作为黄金集发布门禁，并对低置信度输入失败关闭。
- 双通道查询和对账增加延迟，需要在 10 QPS 问答提交压测中单独观测两通道耗时、冲突率和人工复核率。
