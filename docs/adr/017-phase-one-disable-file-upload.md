# ADR-017：第一阶段停用文件上传能力

- 状态：已接受
- 日期：2026-09-14
- 负责人：服务团队
- 决策人：用户确认
- 取代：ADR-009 在第一阶段范围上的结论

## 背景

第一阶段需求调整为不支持文件上传。现有工程已经包含文件上传、文件引用、开发本地存储和历史附件展示代码，但真实 OBS、安全扫描、解析和 OCR 尚未完成生产联调。

## 决策

1. 第一阶段前端不展示上传按钮，不处理拖拽文件，也不调用临时文件接口。
2. 第一阶段问题请求只发送 `agentType` 和 `question`；后端拒绝非空文件引用。
3. `TemporaryFileController` 受 `app.file.upload-enabled` 控制，所有一期环境默认值为 `false`，因此不注册文件上传、列表和删除路由。
4. 不执行破坏性数据库迁移，不删除文件领域模型和适配器。已有文件表、关联表和历史消息附件投影只用于兼容开发期数据和后续扩展。
5. OBS、文件安全扫描、Excel 输入、文本解析、扫描 PDF/图片 OCR 和 HiAgent 文件读取整体顺延到后续阶段，届时重新评审接口、安全和生命周期契约。

## 后果

- 一期范围和外部依赖减少，OBS/OCR 不再是一期发布阻塞项。
- 手工绕过前端调用文件上传路径时得到未注册资源响应；问题请求携带文件引用时得到 `400`。
- 已经产生的开发附件数据不会因本次范围调整丢失，历史消息仍可进行安全只读展示。
- 后续重新启用时必须显式配置开关，并重新完成前端、接口、权限、安全、容量和真实环境验收。

## 验证

- 前端组件测试证明上传按钮和文件选择控件不存在。
- 前端网关测试证明问题请求不发送 `files` 字段。
- Spring MVC 运行时测试证明默认配置未注册文件上传路径。
- 控制器测试证明非空文件引用不能进入问答用例。

## 回滚或取代

若后续阶段恢复文件能力，应新增 ADR 取代本决策，而不是仅修改运行开关。新决策必须冻结 OBS、恶意文件检测、解析/OCR、权限、保留期、审计和失败补偿契约。
