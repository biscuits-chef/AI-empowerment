# ADR-009：一期临时文件上传采用持久元数据与对象存储端口

- 状态：已接受
- 日期：2026-09-01
- 负责人：服务团队
- 决策人：用户确认
- 关联需求：第一阶段支持附件上传

## 背景

一期已确认支持用户在会话内上传临时文件。文件既可能是 Excel 产品编号等查询参数，也可能是需要引用和冲突核验的证据。当前前端只有禁用入口，后端没有文件 API、元数据或问题关联；真实 OBS、安全扫描、解析和 OCR 契约仍待确认。

## 决策驱动因素

- 文件必须按认证用户和会话隔离，不能依赖浏览器本地状态。
- 上传与问题提交必须使用稳定文件 ID，禁止前端传递对象键或签名 URL。
- 查询输入和证据角色必须显式保存，避免把批量编号误当事实证据。
- 外部 OBS 和 OCR 未确认时仍需支持本地开发联调，同时生产失败关闭。

## 决策

1. 通过 V5 前向迁移增加 `qa_file` 和 `qa_question_file`；GoldenDB 保存元数据、状态、摘要、归属、幂等键和问题文件不可变关联。
2. 上传 API 使用 `multipart/form-data` 与 `Idempotency-Key`，一期限制单文件 1 MiB、单问题最多 5 个附件，并校验扩展名、声明类型和文件头。
3. 文件用途为 `AUTO`、`QUERY_INPUT` 或 `EVIDENCE`。问题提交只携带 `fileId + usage`，服务端再次校验 Owner、会话归属和 `READY` 状态。
4. 文件字节通过 `ObjectStoragePort` 保存。开发环境使用受限本地适配器；测试和生产没有真实 OBS 适配器时失败关闭。
5. 开发环境可通过明确开关让完成基础校验的文件进入 `READY`，仅用于前后端联调。测试和生产固定禁止该开关，文件在完成安全扫描、解析或 OCR 前保持 `STORED`。
6. 对象写入失败时把元数据标记为 `FAILED` 并尝试补偿删除；删除先逻辑标记 `DELETE_PENDING`。未被问题引用的对象立即尝试删除，已被问题引用的对象保留到回答处理和留存期结束，后续生产实现需由持久清理任务和孤儿对象对账收敛。
7. 用户提问受理后，前端立即把已提交附件作为该条用户消息的一部分展示；历史消息接口通过 `qa_question_file` 恢复相同元数据。接口不返回对象键或 URL，已逻辑删除的附件仍保留历史关联并显示 `DELETE_PENDING`。

## 后果

- 正面影响：一期附件交互、接口、持久元数据和问题引用可端到端联调；生产 OBS/OCR 可以在不改变核心契约的情况下替换适配器。
- 负面影响：当前开发适配器不解析文件内容，不能证明 Excel、OCR 或证据检索已经完成。
- 后续工作：接入真实 OBS、恶意文件检测、持久解析/OCR 任务、查询输入与证据产物、短期签名 URL、文件状态事件和生命周期清理。

## 验证

- 应用测试覆盖大小、类型、文件头、幂等和跨用户拒绝。
- MVC/接口适配器测试覆盖 multipart 上传和问题文件引用。
- MyBatis-Plus 集成测试覆盖 V5 元数据、状态、Owner 隔离和问题关联。
- 前端测试及真实浏览器覆盖选择、上传、用途切换、删除、随问题提交、发送后即时展示和重新进入会话后的恢复。

## 回滚或取代

前端可通过回滚附件入口停止新上传；V5 表保持向后兼容，不执行破坏性回滚。真实对象存储与处理任务接入时可以用新 ADR 取代开发适配器部分，但必须保留 Owner 隔离、稳定文件 ID、用途分离和失败关闭不变量。
