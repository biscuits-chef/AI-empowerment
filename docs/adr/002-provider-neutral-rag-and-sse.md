# ADR-002：采用供应商无关的检索增强问答与两步式 SSE

- 状态：已接受
- 日期：2026-08-19
- 负责人：TBD
- 决策人：架构负责人（待签署）
- 关联需求：FR-005 至 FR-016

## 背景

知识检索已确定接入公司提供的知识库平台，知识上传维护由平台负责；具体平台契约和业务数据源尚未确定。本 ADR 作出时大模型平台尚未确认，后续 ADR-004 已确定通过公司 HiAgent 运行态 API 接入。第一阶段仍需建立可测试、可替换且支持流式回答的核心边界。

## 决策驱动因素

- 不将领域代码绑定到具体模型或知识库产品。
- 支持幂等提交、断线重连和回答快照。
- 防止模型执行任意 SQL。
- 在外部依赖未配置时安全失败。

## 备选方案

### 单个 POST 长连接直接生成

- 收益：接口数量少，实现简单。
- 风险：浏览器续接、幂等提交、异步恢复和回答快照处理困难。

### 两步式提交与订阅

- 收益：问题先持久化；生成与连接解耦；支持回答状态、重放和重新生成。
- 风险：需要事件存储和额外状态管理。

## 决策

使用供应商无关的知识检索、受控业务查询和大模型端口。问题提交返回 `202` 与回答 ID，客户端再通过 GET SSE 订阅事件。生产事件流使用 Redis Stream 或经批准的等价机制；内存适配器仅用于本地开发。

## 后果

- 外部厂商变更只影响出站适配器。
- 业务数据库只能通过已批准的查询目录访问。
- 生产发布前必须完成 Redis 事件适配器、统一认证和真实依赖契约测试。

## 验证

- 应用服务测试证明调用顺序、幂等、失败与不完整状态。
- API 测试证明 `202` 契约和 SSE 事件格式。
- 真实环境测试证明跨实例重放、网关超时与容量。

## 回滚或取代

若基础设施提供统一的持久化流式任务平台，可用新 ADR 取代 Redis 事件实现，但必须保留入站/出站端口和回答事实数据。
