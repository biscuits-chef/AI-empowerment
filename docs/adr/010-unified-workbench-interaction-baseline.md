# ADR-010：统一工作台交互与恢复基线

- 状态：已接受
- 日期：2026-09-03
- 决策输入：飞书《产品需求文档》与后续产品确认

## 背景

一期智能问答需要进入统一 AI 工作台，并为后续智能问数、合同审核、合同差异比对和申赎确认单处理预留入口。飞书文档与现有实现对登录页面、会话创建时机、执行中会话删除、长列表加载和刷新恢复存在需要统一的表述。

## 决策

1. 未认证用户跳转公司统一认证页面。一期不建设本系统登录页；是否增加自有登录页后续单独决策。开发环境保留由服务端配置的模拟用户，测试和生产禁止模拟认证。
2. Agent 目录来源已由后续 [ADR-011](011-frontend-agent-catalog-and-backend-routing.md) 调整为前端本地配置；后端不再提供目录接口，并通过问题请求中的 `agentType` 独立校验和路由。
3. “新建聊天”只创建前端空白草稿。第一次有效提问时先创建并持久化会话，再提交问题；没有首问的草稿不落库。
4. 会话列表使用服务端不透明稳定游标分批加载；前端使用虚拟滚动，只渲染可见区及缓冲行，同时保留“今天、昨天、更早”分组。
5. 回答事件先持久化到 GoldenDB，再推送给本实例订阅者。历史消息返回执行阶段与来源产物，刷新或重新进入会话时恢复执行过程、人工复核提示、产物和真实回答状态；活动回答继续按最后事件 ID 重放。
6. 会话存在 `PENDING`、`RETRIEVING`、`QUERYING`、`GENERATING` 或 `CANCEL_REQUESTED` 回答时禁止删除。后端返回 `409`，固定中文提示为“会话正在执行，请停止后删除”。前端不得自动替用户停止。

## 影响

- 空白草稿不会污染历史列表，首问创建失败时不得继续提交问题。
- 删除保护必须由后端状态校验兜底，不能只依赖前端按钮状态。
- GoldenDB 是恢复事实来源；Redis 未来只承担跨实例即时分发和有界重放，不成为唯一数据源。
- 当前持久事件解决刷新后的阶段与产物恢复，但本机任务投递和本实例订阅尚不能满足进程重启续跑与多副本即时推送；生产前仍需持久生成任务和 Redis Stream（或等价机制）。

## 验收

- 非智能问答 Agent 不产生会话或执行请求。
- 首次有效提问只产生一个会话，重复提交由幂等语义保护。
- 长会话列表按游标连续、无重复地加载，DOM 节点数量不随总会话数线性增长。
- 刷新后可恢复执行阶段、来源产物、人工复核和回答状态，活动回答可继续跟随。
- 活动会话删除返回固定 `409` 提示；停止到达终态后可以删除。
