# ADR-018：首次建会话与提交问题合并为统一接口

- 状态：已接受
- 日期：2026-09-14
- 决策人：用户确认

## 背景

原流程在首次提问时先调用独立创建会话接口，再调用按会话提交问题接口。一次用户操作对应两次写请求；如果创建成功但提交失败，会留下空会话，并且网络重试可能重复创建会话。非首次提问只需要提交问题，不应因此改变既有会话语义。

## 决策

前端统一调用 `POST /api/v1/questions/submission`：

- Header `Idempotency-Key` 必填。
- Body 的 `chatId` 为空表示首次提问，非空表示向已有会话追问。
- Body 始终携带 `question`；首次提问同时携带 `agentType`，后续提问省略该字段；第一阶段拒绝非空 `files`。
- 首次提问在一个数据库事务中创建或复用会话、持久化问题与回答；非首次提问锁定并校验已有会话后沿用相同问答链路。
- 响应为 `QuestionSubmission`，同时返回 `conversation`、`conversationCreated` 和 `answer`；Header `Location` 指向回答 SSE 地址。
- 事务提交后才投递异步问答编排，避免任务读取未提交数据。
- `qa_conversation` 增加可空的 `creation_idempotency_key`，并以 `(owner_id, creation_idempotency_key)` 建唯一索引；V20 增加不可空 `agent_type` 保存首次选择。回答继续保存请求指纹。相同用户、幂等键和请求返回原会话与原回答，同键不同请求返回 `409 IDEMPOTENCY_CONFLICT`。
- 移除旧的 `POST /api/v1/chats/creation` 和 `POST /api/v1/chats/{chatId}/questions` 映射，不保留双写或兼容别名。

## 影响

- 点击“新建会话”只更新前端本地状态，不产生后端请求；首次发送问题只需一次普通 POST，再建立一次 SSE 连接。
- 首次提问不会因两段写流程留下空会话，并发重试不会创建重复会话或回答。
- 非首次提问只传已有 `chatId` 和问题，后端从会话读取固定 Agent 类型；问题校验、上下文、状态机、双通道查询、停止与重生成逻辑保持不变。
- 前后端必须在同一发布窗口升级；旧客户端不能继续使用已移除的接口。

## 验证

- 服务测试覆盖首次提问创建与幂等复用、已有会话追问不创建新会话。
- 持久化测试覆盖用户与创建幂等键唯一约束。
- 控制器映射测试确认统一路径存在、两个旧路径不存在。
- 前端网关和页面测试覆盖首次提问传 `chatId=null + agentType`、后续追问只传已有 ID 和问题，并只发起一次统一提交请求。

## 回滚

回滚必须同时恢复前后端旧契约，并使用新的 ADR 说明迁移策略。V18 新增列可保持为空，不需要破坏性回滚；不得删除已经用于幂等审计的数据。
