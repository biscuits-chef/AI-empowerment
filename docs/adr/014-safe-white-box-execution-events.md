# 架构决策：提供安全白盒执行事件

- 状态：已接受
- 日期：2026-09-08
- 决策人：项目组

## 背景

用户需要了解智能问答在意图识别、知识库检索、GoldenDB 查询、证据核验和回答生成中的真实进度。现有开始事件不足以表达完成状态、结果数量、流程版本和耗时；直接输出内部日志则可能泄露提示词、SQL、服务地址和业务正文。

## 备选方案

1. 返回完整内部日志和模型推理：透明度高但不可控，存在严重安全与合规风险。
2. 仅保留粗粒度开始事件：兼容成本低，但用户无法核验过程。
3. 增加不含业务正文的结构化摘要事件，并继续使用已有持久事件和 SSE 重放机制。

## 决策

采用第三种方案。新增流程计划、知识库完成、业务查询完成、证据核验开始和回答生成完成事件；扩展意图和证据核验事件值，提供稳定编码、置信度、条件数量、结果数量及冲突数量。所有事件在推送前继续写入 GoldenDB，历史消息返回同一轨迹。

白盒事件严禁包含系统提示词、思维链、原始 SQL、服务地址、密钥和证据正文。`generation_completed` 只表示内容生成完成，最终回答必须以 `completed` 及持久快照为准。

## 后果

协议仅新增事件并扩展原有字符串值，对忽略未知事件的旧客户端保持兼容。新客户端可计算阶段耗时并展示五阶段时间线。旧历史事件不会补造结果数量。

## 验证

服务测试验证完整流程事件及安全摘要值；持久事件、历史恢复、SSE、停止和重放测试继续通过全量质量门禁。
