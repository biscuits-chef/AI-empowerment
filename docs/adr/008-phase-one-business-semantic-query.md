# ADR-008：一期采用受控业务语义查询计划

- 状态：部分被 ADR-013 取代
- 日期：2026-09-01

## 背景

智能问答需要直接查询由数据中台同步到 GoldenDB 的产品和交易数据。长期目标是建设以业务语义层为核心、关系图谱为支撑、Query Planner 为执行中枢的企业级自然语言查询能力，但一期只需覆盖产品基础信息、产品最新结构化信息和交易员查询。

现有 `BusinessDataQueryPort` 只有演示空实现。直接让大模型输出 SQL 会绕过字段口径、Join 关系、数据权限和成本控制，也与项目已有安全约束冲突。真实 GoldenDB 表、视图和权限字段尚未最终确认，代码不能自行猜测。

## 决策

1. 保留现有问答应用服务和 `BusinessDataQueryPort`，仅替换端口内部实现。
2. 一期业务语义目录只定义产品、交易两个实体和经批准的标准字段。
3. 语义解析器只把已消歧意图转换为实体、字段和实体引用，不生成物理 Schema 或 SQL。
4. Query Planner 只允许 `PRODUCT_LOOKUP` 和 `TRADE_LOOKUP` 两类逻辑计划。
5. SQL Compiler 只允许选择 `SELECT_PRODUCT_FACTS` 和 `SELECT_TRADE_FACTS` 两个固定 MyBatis Statement，不接收自由 SQL 文本。
6. 所有用户值使用 MyBatis `#{}` 参数绑定；SQL 同时绑定认证用户、实体引用和结果上限。
7. 数据平台提供 `biz_semantic_product_v` 和 `biz_semantic_trade_v` 授权语义视图；Flyway 不管理外部视图。
8. 语义模型版本写入计划标识和业务事实追溯信息。
9. 真实业务查询默认关闭，未配置时非演示环境失败关闭。

## 一期不包含

- 从大量原始表执行向量化 Schema 检索。
- 自由选择跨表 Join 路径。
- 任意指标、维度、聚合、排名、趋势或自然语言取数。
- 大模型生成物理表名、列名、权限条件或 SQL。
- 运行时自动接受未经审批的 Schema 或关系变化。

## 结果

产品视图、产品计划类型和产品物理查询目标已由后续确认调整，参见 ADR-013；交易兼容路径及“禁止模型生成任意 SQL”的决策继续有效。

优点：

- 当前智能问答可以通过稳定语义字段接入 GoldenDB。
- 查询计划和物理语句均可审查、测试、版本化和审计。
- 模型不能改变表、字段、Join 或权限条件，降低幻觉和错误关联风险。
- 未来可以在保持问答端口不变的情况下扩展 Schema 检索和关系规划。

代价：

- 新增字段和查询类型必须发布语义模型并修改批准计划。
- 一期无法满足通用自然语言取数需求。
- 数据平台必须建设并维护授权语义视图。

## 验证

- 单元测试覆盖产品/交易语义解析、字段白名单、一期关系、计划限额和固定语句编译。
- MyBatis 集成测试覆盖参数绑定、产品名称/代码查询、交易流水号查询、Owner 行过滤和结果上限。
- 生产启用前必须在真实 GoldenDB 完成视图契约、SQL 方言、只读账号、权限正确性、`EXPLAIN`、超时和容量验证。
