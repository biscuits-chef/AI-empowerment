# ADR-012：采用场景计划驱动的节点化问答工作流

- 状态：已接受
- 日期：2026-09-03
- 负责人：项目技术负责人
- 决策人：项目负责人
- 关联需求/问题：在保持一期双通道查询行为不变的前提下，为未来纯 LLM、制度库等查询场景建立可扩展编排边界

## 背景

原有问答流程在 `QuestionAnswerService.generate` 中固定串联问题理解、知识库查询、GoldenDB 查询、证据对账和模型生成。该方式能够支撑一期双通道问答，但继续加入纯 LLM、指定知识库、附件增强或合同类流程会使应用服务积累大量场景分支。

一期仍只允许 `SMART_DATA`，并且只执行知识库与 GoldenDB 双通道查询。当前不能为了尚未开放的场景增加外部接口、数据库结构或第三方 Agent 框架，也不能改变追问、停止、SSE、证据不足、冲突提示和答案持久化语义。

## 决策驱动因素

- 新增场景时应主要新增执行计划，而不是修改所有既有节点。
- 节点只承担单一能力，不能反向依赖不断增长的场景枚举。
- 保持现有六边形端口、状态机、停止语义和流式协议兼容。
- 执行器需要统一处理节点顺序、前置条件跳过、合法短路、停止检查和执行轨迹。
- 当前 Java 8/Spring Boot 2.7 基线下不引入需要更高 JDK 或额外运行时的图工作流框架。

## 备选方案

### 方案 A：每个节点判断场景类型的责任链

- 收益：实现直接，线性流程容易理解。
- 成本/风险：场景与节点形成多对多耦合；每次新增场景都可能修改所有节点；场景完整流程分散在节点内部；不利于后续并行分支和计划版本管理。

### 方案 B：场景计划、通用执行器与无场景感知节点

- 收益：场景集中声明节点顺序和版本；节点仅判断自身数据前置条件；执行器统一记录开始、成功、跳过和失败；现有出站端口可以直接复用。
- 成本/风险：新增少量应用层抽象；当前执行轨迹只存在于单次类型化上下文，跨进程恢复仍依赖后续持久生成任务建设。

### 方案 C：立即引入第三方 Agent/图工作流框架

- 收益：能够直接获得复杂分支、检查点和图执行能力。
- 成本/风险：一期只有一个确定性场景，引入成本和运行复杂度高；当前 Java 8 基线与候选框架要求不一致；可能与公司 HiAgent 自身编排能力重叠。

## 决策

采用方案 B：

1. `AgentType` 负责入口校验，并将已开放 Agent 映射为后端 `QueryScenario`；两者不能混为同一概念。
2. `ScenarioPlanRegistry` 集中注册带版本的场景计划。第一阶段只注册 `DUAL_CHANNEL_QA` 版本 `1`，不注册纯 LLM、制度库或其他场景。
3. 双通道计划固定包含问题理解、知识库检索、业务数据查询、证据对账和回答生成五个节点。
4. `QuestionWorkflowEngine` 按计划执行节点，统一在节点之间检查停止请求，处理 `shouldExecute` 跳过和 `STOP` 合法短路，并把节点生命周期写入 `QuestionWorkflowContext`。
5. 节点不得判断具体场景枚举。场景是否包含节点由计划决定；节点只允许基于自身输入数据和前置条件决定是否跳过。
6. `QuestionAnswerService` 继续拥有回答状态转换、SSE 事件、部分答案持久化、追问上下文和完成/失败收敛，保证对外行为兼容。
7. 本次不新增数据库迁移和第三方依赖。计划版本和完整节点轨迹的跨重启持久化与持久生成任务一起演进。

## 后果

- 正面影响：双通道主流程从单个硬编码方法迁移为可独立测试的节点；后续场景可以组合已有节点或新增节点；跳过和短路语义集中且可验证。
- 负面影响：当前计划仍是串行列表，知识库与数据库并行查询尚未实现；应用服务仍需把节点生命周期映射到既有回答状态和 SSE 事件。
- 后续工作：新增真实场景前必须明确权限、证据规则、失败语义和前端契约，并新增独立 ADR 或更新本决策；需要并行、循环、人工暂停或跨服务检查点时再评估轻量 DAG 或图工作流框架。

## 验证

- 工作流执行器测试验证双通道计划顺序、计划版本、节点生命周期记录、跳过后继续和合法短路。
- 问答应用服务回归验证原有知识库、业务库、模型调用顺序及追问、证据不足、冲突、停止、幂等和失败终态。
- Spring 上下文与架构测试验证全部节点可装配，应用层不依赖适配器，领域层不依赖框架。
- 完整执行 `mvn -B -ntp clean verify`，通过 Checkstyle、PMD/CPD、SpotBugs、JaCoCo、ArchUnit 和中文注释门禁。

## 回滚或取代

回滚时可让 `QuestionAnswerService` 恢复原固定编排并删除应用层工作流组件，不涉及数据库回滚或 API 变更。当场景需要动态工具选择、并行图、循环、长时间人工暂停或跨服务检查点时，由新的 ADR 评估并取代当前串行计划执行器。
