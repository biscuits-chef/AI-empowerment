# ADR-020：Agent 类型在会话首次提问时固化

## 状态

已接受，2026-09-14，由用户明确确认。

## 背景

Agent 选择决定会话使用的后端处理场景。原契约要求每次提问都传递 `agentType`，既让已有会话页面继续暴露无效的选择控件，也允许客户端在同一会话中反复发送不同类型。只在前端隐藏选择器不能形成可靠约束，后端必须拥有会话类型这一事实。

## 决策

1. Agent 选择器只在新建会话首次提问前展示。进入已有会话后隐藏选择器，前端状态层也拒绝切换。
2. 首次调用 `POST /api/v1/questions/submission` 时，`chatId=null` 且 `agentType` 必填；第一阶段仅允许 `SMART_DATA`。
3. Flyway V20 为 `qa_conversation` 增加不可空 `agent_type`。首问在创建会话的同一事务中保存该类型。
4. 已有会话的后续提问只发送 `chatId` 和 `question`，不发送 `agentType`。后端锁定并校验会话归属后，从 `agent_type` 选择处理场景。
5. 为兼容切换窗口内的旧客户端，后端暂时允许已有会话请求携带与持久化值相同的类型；携带不同类型时以 `400` 拒绝，不创建回答或调用下游依赖。
6. 重新生成同样读取会话中的固定类型，不接受新的类型参数。

## 数据迁移与兼容性

V20 使用 `SMART_DATA` 默认值兼容历史会话和短暂运行的旧版本应用。该默认值只代表一期全部存量会话均属于智能问数，不能在未来多 Agent 阶段继续作为静默兜底。开放第二种 Agent 前必须确认所有写路径均显式保存类型，并通过新的前向迁移评审是否移除默认值。

## 验证

- 前端组件测试验证新建会话显示选择器、已有会话隐藏选择器。
- 前端网关测试验证首问发送 `agentType`，后续问题请求体不含该字段。
- MVC 测试验证首问缺少类型返回 `400`，已有会话缺少类型能够受理。
- 应用服务测试验证后续提问从会话解析类型，试图切换类型时失败关闭。
- MyBatis 集成测试验证 Agent 类型写入后可被读取，迁移契约测试验证 V20 及 ResultMap。

## 回滚

前端可以回滚为继续发送同一 `agentType`，新后端仍兼容该请求。后端二进制回滚时保留 V20 新列及默认值，旧代码会忽略该列；不得通过破坏性迁移删除会话类型数据。
