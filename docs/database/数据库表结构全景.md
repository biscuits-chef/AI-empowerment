# 数据库表结构全景

## 1. 文档范围

本文以当前 Flyway `V1`～`V21`、原生 MyBatis 持久化 Record、Mapper 和一期生产目标为准，分为：

1. 已有 Flyway 管理的问答应用表；
2. 数据中台同步的业务快照表；
3. 外部授权视图；
4. 一期生产仍需新增的表与后续阶段预留表；
5. 语义层元数据建议表。

测试资源中的 H2 表和测试视图不属于生产表结构。所有新增结构只能使用新的 Flyway 前向迁移，不得修改已经执行的 `V1`～`V7`。

2026-09-14 范围调整后，一期不支持文件上传。已经落地的 `qa_file`、`qa_question_file` 及其迁移不做破坏性删除，仅用于兼容历史开发数据；一期运行时不注册上传路由、不会创建新的文件关联。文件解析、OBS 和 OCR 相关建议表全部降为后续阶段预留。

统一主键政策：每张表必须且只能使用 `id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY`，禁止 `pk_id`、UUID、外部编码或复合业务键作为主键。资源 UUID 改存 `public_id UNIQUE`；其他原主键改为唯一业务键。数据库自增值不进入 REST、SSE 资源标识、OBS 对象键或领域模型。

持久化 Record 字段以数据库列名为唯一命名依据，并按 Java 小驼峰转换：删除下划线，将下划线后的首字母大写。例如 `id -> id`、`public_id -> publicId`、`app_conversation_id -> appConversationId`、`message_id -> messageId`。不得为同一物理列另起 `databaseId`、`providerMessageId` 等语义别名。领域对象和接口 DTO 不受物理列名直接约束，但必须由持久化适配器完成显式映射。

## 3. 逻辑关系

```text
qa_conversation
  ├─ 1:N qa_message
  ├─ 1:N qa_answer
  ├─ 1:1 qa_conversation_context
  └─ 1:N qa_file

qa_message（USER 问题）
  ├─ 当前实现 1:1 qa_answer；重新生成会复制原问题并创建新的问题消息和回答
  └─ N:M qa_file，通过 qa_question_file 关联

qa_answer
  ├─ 1:1 qa_answer_feedback（每个用户当前评价）
  ├─ 1:1 qa_answer_cancel_task
  └─ 1:N qa_answer_event

dws_product_info_d
  └─ 由数据中台按 DT 同步；通过产品代码/名称/简称/全称被查询，不与应用表建立物理外键
```

当前 DDL 未声明物理外键。逻辑引用完整性由事务和应用服务维护，以避免目标 GoldenDB 分片、同置和在线变更能力未确认时引入不兼容约束。

## 4. 已落地应用表数据字典

### 4.1 `qa_conversation` 会话表

| 字段 | 类型 | 允许空 | 键/索引 | 说明 |
|---|---|---:|---|---|
| `id` | `BIGINT AUTO_INCREMENT` | 否 | PK | 数据库物理主键，不对外暴露 |
| `public_id` | `VARCHAR(36)` | 否 | UK | 会话 UUID，供领域和 API 寻址 |
| `owner_id` | `VARCHAR(128)` | 否 | `idx_qa_conversation_owner_updated` | 可信认证用户标识 |
| `creation_idempotency_key` | `VARCHAR(128)` | 是 | 与 `owner_id` 组成 UK | 首次提问原子创建会话时的幂等键；历史会话或内部普通创建可为空 |
| `agent_type` | `VARCHAR(32)` | 否 |  | 首次提问选择并固化的 Agent 类型；后续提问只读且不可修改，历史数据默认 `SMART_DATA` |
| `title` | `VARCHAR(100)` | 否 |  | 会话标题；默认取首次有效提问前 100 个 Unicode 字符 |
| `created_at` | `TIMESTAMP(6)` | 否 |  | 创建时间 |
| `updated_at` | `TIMESTAMP(6)` | 否 | 复合索引第二列 | 会话活动排序时间 |
| `deleted_at` | `TIMESTAMP(6)` | 是 |  | 逻辑删除时间；为空表示有效 |

索引：主键 `id`；唯一索引 `public_id`；唯一索引 `(owner_id, creation_idempotency_key)`；普通索引 `(owner_id, updated_at, public_id)`。MySQL/GoldenDB 唯一索引允许多条 `NULL`，因此普通创建和历史数据不受影响；首次提问并发重试则按用户与幂等键收敛到同一会话。会话分页使用公开 UUID 作为同时间排序键，避免暴露数据库序列。

## 5. 产品业务快照表

### 5.1 `dws_product_info_d`

该表由 Flyway 创建空表和索引，数据中台负责每日同步完整快照。物理主键为 `id BIGINT AUTO_INCREMENT`，业务唯一键为 `(PRDC_CD, ACCT_DT)`；同步程序必须使用显式列清单并忽略 `id`。

| 字段 | 类型 | 允许空 | 说明 |
|---|---|---:|---|
| `id` | `BIGINT AUTO_INCREMENT` | 否 | 数据库物理主键 |
| `PRDC_CD` | `VARCHAR(80)` | 否 | 产品代码 |
| `FML_PRDC_CD` | `VARCHAR(60)` | 是 | 母产品代码 |

## 9. 统一数据库规范

- 字符集目标为 `utf8mb4`；排序规则 `utf8mb4_0900_ai_ci` 必须在真实 GoldenDB 版本验证，不支持时由 DBA 统一替换。
- 资源 UUID 以 `public_id VARCHAR(36)` 保存并建立唯一约束；只用于公开寻址，不作为物理主键。
- 应用时间统一存 UTC，接口返回 ISO-8601；业务日期使用 `Asia/Shanghai`，`dws_product_info_d` 三个日期字符串固定为 `yyyy-MM-dd`。
- 所有用户输入通过 MyBatis `#{}` 绑定；禁止 `${}`、动态表名、动态列名和模型生成 SQL 直接执行。
- 所有会话、回答、文件和审计查询必须带可信 `owner_id` 或服务端权限条件。
- 大文本、JSON、OCR 和证据字段禁止完整写入普通日志；备份、导出和运维查询同样受数据权限控制。
- 删除默认采用逻辑删除或保留策略；对象物理删除、数据库归档和审计保留期必须由安全、合规和业务签署。
- Flyway 只前向迁移。V8～V17 是经用户批准的同名主键合同切换，必须在停写维护窗口逐版本核验；V18 为首次提问统一接口增加可空幂等列与唯一键；V19 对齐 HiAgent 回答元数据列；V20 为会话增加不可空 `agent_type`，以 `SMART_DATA` 兼容回填历史会话；V21 将产品快照表字段与 DataHub `ProductInfoDto` 实体类对齐（`EXPR_DT`、`END_PRD_EXPR_DT`、`ACCT_DT`）并重建索引。后续一般变更仍采用扩展、迁移/回填、切换读取和收缩。
- 每张新表必须在真实 GoldenDB 确认分片键、同置策略、索引长度、在线 DDL、事务、锁、备份和故障切换。
