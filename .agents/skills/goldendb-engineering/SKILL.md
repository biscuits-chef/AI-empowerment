# GoldenDB 工程

## 工作流

1. 记录真实 GoldenDB 的产品版本、精确版本号、兼容模式、拓扑、分片/分布规则和不支持的 MySQL 特性。将缺失信息标记为环境验证项，不得作为假设。
2. 定义访问模式、基数、增长、保留、唯一性、一致性和事务不变量。
3. 根据真实查询设计主键、分布 Key 和索引。避免无界扫描、`SELECT *`、大规模 Offset 分页，以及缺乏证据的跨分片事务。
4. 使用显式 SQL 和有界结果集。为关键查询保留真实 GoldenDB `EXPLAIN` 证据。
5. 创建新的只向前 Flyway 迁移。采用“扩展—迁移—收缩”，并保证应用在整个发布窗口内兼容。
6. 缩短事务时间；对瞬时故障进行分类，只对幂等操作按有界预算重试。
7. 根据数据库连接总预算计算所有副本的 HikariCP 规模；有意识地设置连接、校验、语句和请求截止时间。
8. 在合适环境中测试迁移、回滚/前滚、锁、死锁、故障切换、备份/恢复和代表性数据量。

## 证据

报告表结构/SQL 变更、兼容性依据、查询计划、连接池计算、迁移顺序、故障测试，以及仍需在真实 GoldenDB 执行的全部检查。
