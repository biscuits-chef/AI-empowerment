# 功能开发

## 工作流

1. 将请求转化为可度量的验收标准，并把每项标准映射到测试。
2. 检查相邻代码、契约、迁移和测试；现有模式合理时继续复用。
3. 先建模领域值与入站/出站端口，再处理厂商特定细节。
4. 实现应用编排，显式说明事务、幂等性、超时和部分失败语义。
5. 实现适配器时，禁止将框架或 SDK 类型泄漏到领域端口。
6. 按需补充兼容 RFC 7807 的错误、输入/资源上限、安全日志、指标和配置。
7. 先添加单元测试，再根据风险添加架构、集成、契约、并发或故障注入测试。
8. 迭代时运行聚焦测试，最后运行 `mvn -B -ntp clean verify`。
9. 审查完整差异，覆盖兼容性、安全、数据安全、可运维性、迁移和回滚，并更新文档。

## 约束

不得虚构业务策略，不得增加推测性抽象，不得削弱门禁、暴露密钥、编辑已执行的 Flyway 迁移，也不得让领域代码耦合 Spring 或厂商 SDK。
