# Redis 工程

## 工作流

1. 明确 Redis 是缓存、协调存储、限流器、队列还是事实来源，并定义权威数据及一致性容忍度。
2. 设计带版本和命名空间的 Key、基数、Value 格式、最大大小、TTL/随机抖动、失效机制和所有权。
3. 定义命中、未命中、陈旧、损坏、超时、故障切换及淘汰行为；缓存不可用时仍须保持正确性。
4. 只有在负载模型确有需要时，才使用请求合并、锁、提前刷新或随机抖动保护热点 Key 和缓存未命中。
5. 请求路径中避免宽范围 Key 扫描和无界命令；对 Pipeline、Lua 脚本、集合和超时设置上限。
6. 有意识地配置拓扑、TLS/认证、客户端连接池、内存、持久化和淘汰策略。
7. 增加延迟、错误、命中率、内存、淘汰、重连、热点 Key 和回退负载指标。
8. 测试序列化演进、损坏值、过期、并发未命中、故障切换和 GoldenDB 回退。

## 完成条件

记录 Key 契约和故障语义，添加聚焦测试，运行质量门禁，并列出必须在共享环境验证的拓扑/负载检查。
