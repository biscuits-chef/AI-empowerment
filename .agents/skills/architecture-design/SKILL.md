# 架构设计

## 工作流

1. 从事实来源文档提取功能需求、质量属性、约束、增长假设和未知项。
2. 提出新抽象前，追踪当前执行路径与依赖路径。
3. 明确定义不变量、所有权、信任边界、数据生命周期和部分失败行为。
4. 对长期有效或逆转成本高的决策比较至少两个可信方案，并评估简单性、可用性、一致性、可运维性、安全、成本和迁移。
5. 保持依赖向内：领域、端口、应用编排、适配器。
6. 明确 GoldenDB 事务/迁移行为、Redis 语义、OBS 一致性/清理、超时、幂等性和可观测性。
7. 仅对长期有效且跨领域的决策使用 `docs/adr/000-template.md` 创建 ADR，不要为常规实现细节创建 ADR。
8. 当新边界需要机械化约束时，新增或更新 ArchUnit 规则。

## 必需输出

返回选定方案、被拒绝的备选方案、必要的图示/数据流、受影响的包、不变量、失败矩阵、迁移/回滚、测试策略，以及尚未解决且需要责任人决定的事项。
