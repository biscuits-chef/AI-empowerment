# 质量工程

## 工作流

1. 先将需求、不变量、边界和失败模式映射到测试证据，再统计覆盖率。
2. 领域/应用决策使用单元测试，HTTP 映射使用 MVC 测试，适配器使用集成/契约测试，依赖规则使用 ArchUnit；负载/故障测试按需在 Maven 之外执行。
3. 保持测试确定性：固定时钟、显式数据、可控随机性、有界等待，不依赖隐藏顺序或共享状态。
4. 修复缺陷时，在可行情况下先用失败的回归测试复现问题。
5. 根据风险测试无效边界、部分失败、重试/幂等性、序列化演进、并发和资源限制。
6. 迭代期间运行聚焦测试，完成前运行 `mvn -B -ntp clean verify`。
7. 诊断 Checkstyle、PMD/CPD、SpotBugs、ArchUnit、JaCoCo、Surefire 或 Failsafe 失败的根因。修复生产代码或测试；没有记录充分的误报理由时不得压制问题。
8. 检查 `target/site` 下的报告与测试报告，明确报告覆盖率排除项和只能在环境中验证的缺口。

## 门禁策略

覆盖率只是最低线，并非正确性证明。不得只为获得绿色构建而降低阈值、跳过测试、放宽规则或增加大范围排除。
