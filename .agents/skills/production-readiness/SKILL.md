# 生产就绪

## 工作流

1. 阅读 `REQUIREMENTS.md`、`ARCHITECTURE.md`、已接受的 ADR、部署文件和 `docs/operations/production-readiness-checklist.md`。
2. 使用负责人和证据验证每个适用的清单条目；标记 `N/A` 时必须说明原因。
3. 区分代码可验证证据与环境证据。不得将本地 MySQL 当作 GoldenDB 故障切换/性能证明，也不得将禁用 OBS 当作集成证明。
4. 审查 SLO/错误预算、容量/余量、超时、重试、幂等性、舱壁、依赖故障、健康检查、优雅停机、备份/恢复、RPO/RTO 和灾难恢复。
5. 审查认证/授权、数据分类、密钥、网络/IAM、供应链、镜像加固和敏感遥测数据。
6. 审查仪表盘、告警、运行手册、责任归属、事件路径、金丝雀/滚动门禁、迁移、回滚/前滚和部署后验证。
7. 运行 `mvn -B -ntp clean verify` 并检查报告。存在关键门禁失败或影响发布的 `TBD` 时，不得标记为生产就绪。

## 输出

先返回发布阻塞项，再返回高优先级后续事项与已接受风险。每项都要写明负责人、必需证据和发布/停止条件。明确结论是“就绪”“有条件就绪”还是“未就绪”。
